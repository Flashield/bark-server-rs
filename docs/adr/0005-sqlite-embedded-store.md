# SQLite (rusqlite, bundled) as the embedded store

One storage engine serves both the upstream-compatible device registry and the new pending-message store (ADR-0002): SQLite via rusqlite with the `bundled` feature, preserving upstream's single-file, zero-external-dependency deployment shape. Chosen over redb (pure KV — per-device ordered pending lists, TTL pruning, and the reserved ack/retry upgrade would mean hand-rolled indexes) and sled (effectively unmaintained since 2024). The second backend, behind a store trait, is **PostgreSQL** — a deliberate deviation from upstream, whose remote backend is MySQL: we consciously give up direct database migration from an existing upstream bark-server instance in favor of our own infrastructure preference (confirmed with the maintainer, 2026-11-10). Upstream's serverless-env single-device backend is dropped as a Heroku deployment artifact — trivially re-addable if ever needed.
