# Reuse upstream APNs credentials, embedded like upstream

The official Bark iOS App only accepts APNs pushes for its own bundle (`me.fin.bark`), which is cryptographically tied to Fin's Apple developer account (AuthKey `LH4T9V5U4R`, TeamID `5U8LBRXG3A`). Since ADR-0003 commits to zero-change compatibility with that app, this server embeds the same signing key, key ID, team ID, and both topics (`me.fin.bark`, `me.fin.bark.watch`) — exactly as upstream does. The key is already public in the MIT-licensed upstream repository, so copying it creates no new exposure. A runtime file/flag override is accepted for anyone who later wants their own account, but embedding keeps the zero-config open-box behavior. Alternative rejected: maintaining our own Apple account + a forked Bark app build — that reintroduces exactly the iOS-side work ADR-0003 exists to avoid.
